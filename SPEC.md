## 1. Product summary

Penny is an accessible mode of a bank's app for blind and low-vision customers. Voice, sound, and touch are primary channels; the screen is secondary. Five system behaviours define it:

1. **Read-Back Rule** — no action executes until Penny states exactly what will happen and receives confirmation.
2. **Action Receipts** — every completed action writes a hash-chained, tamper-evident log entry.
3. **Quiet Mode** — speech is replaced by high-contrast text cards and haptics; short earcons still play.
4. **Haptic grammar** — three named vibration patterns: Confirm, Alert, Attention.
5. **The Glance** — a ≤2-second non-speech earcon that encodes account health, played on open; plus "Play my week", a 5-second stereo sonification of the week's transactions.

Features: **Post Box** (photograph any letter → on-device masking of sensitive digits → AI reading in Summary / Exact / Explain modes → offered account action → confirm → receipt), **Tap & Tell** (simulated card-terminal push announcing the exact amount before approval), **Scam Shield** (scam letters detected, announced, auto-filed), **Layout Lock** (a CI gate that fails the build if the accessibility tree changes without a migration flag), and the **Journey slider** (one screen morphing across three stages of sight loss).

## 4. Design system

**Design intent (so styling is executed with a point of view, not defaults):** the product's hero is *audible*, so the visual layer is deliberately quiet, dark, and oversized — a stage for sound. One accent only. The single visual signature is the **sound-dot**: a 10px amber dot in the header that pulses (scale 1→1.4, 600ms loop) whenever Penny is speaking or playing an earcon. The system font is a deliberate accessibility choice (zero load time, maximal familiarity), so personality comes from scale, spacing, the dot, and copy — never from decorative UI.

Tokens (define as CSS variables in `styles.css`, reference in Tailwind arbitrary values or a small theme extension):

| Token | Value | Use |
|---|---|---|
| `--bg` | `#101418` | app background |
| `--surface` | `#1A2129` | cards |
| `--surface-raised` | `#232B35` | sheets, text cards |
| `--text` | `#F5F7FA` | body (15.6:1 on bg) |
| `--text-dim` | `#9AA7B4` | captions |
| `--amber` | `#FFB703` | ONLY accent: actions, focus, dot |
| `--amber-press` | `#E09E00` | pressed state |
| `--danger` | `#FF5C5C` | scam/tamper only |
| `--hairline` | `#2C3540` | dividers |

Typography: `font-family: Arial, "Helvetica Neue", system-ui, sans-serif`. Scale (px): 16 caption · 18 body (root) · 22 card title · 28 screen title (h1) · 40 balance · 64 Journey health word. Line-height 1.4. Sentence case everywhere.

Shape & interaction: card radius 16px; pill buttons radius 999px; **minimum tap target 48×48px** (primary buttons 56px tall); focus ring `3px solid var(--amber)` with 2px offset on every focusable element; buttons with amber background use `#101418` text. Motion: 150–200ms ease-out only; wrap all animation (including the sound-dot pulse) in `@media (prefers-reduced-motion: no-preference)`.

Copy rules: buttons name the exact outcome ("Order replacement card", "Double-tap to confirm", never "Submit"/"OK"). An action keeps one name through its whole flow: order → read-back → receipt all say "Replacement card". Errors state what happened and the fallback taken, no apologies.

## 6. Audio architecture

### 6.1 Unlock (mandatory — browsers block audio before a gesture)

`Splash.tsx` renders full-screen on first load of a session: Penny wordmark (28px), the sound-dot, caption "Tap anywhere to open". The whole screen is one button (`aria-label="Open Penny"`). On tap, in order: `await Tone.start()`; play a 30ms silent buffer through an `HTMLAudioElement` (unlocks media playback on Android); `speechSynthesis.cancel()` then `speechSynthesis.resume()`; set `session.unlocked = true`; play fixed line `greet` (skipped in Quiet Mode); navigate to Home; run `glance()` once (`session.glancePlayedThisSession = true`). No audio API may be called anywhere before `session.unlocked` is true.

### 6.3 `lib/audio.ts` — the single speech gateway

`speak(input: { id?: FixedLineId; text?: string })`:

1. Mirror the exact text into the aria-live region (ALWAYS, in every mode — screen-reader parity).
2. If `settings.quietMode` → render a `TextCard` with the text; play **no** speech; return. (Earcons and haptic fallback clicks are exempt — they route through `earcons.ts`/`haptics.ts`, not `speak()`.)
3. Else if `id` → play `public/audio/{id}.mp3` via a shared `HTMLAudioElement`.
4. Else → `POST /api/tts { text }` → play returned `audio/mpeg` blob; cache blobs in-memory keyed by text.
5. On ANY failure (missing file, network, non-200): fall back to `speechSynthesis` — `SpeechSynthesisUtterance(text)`, `lang = "en-GB"`, rate 1.0, prefer a voice whose `lang` starts with `en-GB`.
6. While anything is playing, set a module-level `speaking` flag consumed by `SoundDot.tsx`; clear on `ended`/`error`.

Queue: one line at a time; sequential calls await the previous line's end.

## 7. Earcons — `lib/earcons.ts`

Master output: `Tone.getDestination().volume.value = -8`.

### 7.1 `glance(account, week)` — ≤2s, plays even in Quiet Mode

Health = `balance − sum(billsDueThisWeek.amount)` → `> 500` **steady** · `0–500` **tight** · `< 0` **risk**.

- Motif synth: `Tone.Synth({ oscillator: { type: "triangle" }, envelope: { attack: 0.005, decay: 0.08, sustain: 0.2, release: 0.3 } })`. Three notes, 0.16s duration, onsets at t+0s / t+0.22s / t+0.44s: steady = C4 E4 G4 (rising major), tight = E4 E4 E4 (level), risk = G4 Eb4 C4 (falling minor).
- If `billsDueThisWeek.length > 0`: A5, 0.09s, at t+0.72s (the "bill ping").
- If any tx in the last 7 days has `isAnomaly`: dyad C5+F#5 (tritone), 0.12s, at t+0.95s, second synth at −4dB relative (the "anomaly tick").
- After completion, post to aria-live: `"Steady. One bill this week. One unusual payment."` (compose from actual data: health word + bill count + anomaly count; omit absent parts).

With the §5 fixtures the demo Glance = rising triad + bill ping + anomaly tick.

### 7.2 `playWeek(week, onNote)` — 5s stereo sweep

- Note onset: `0.3 + 4.4 × dayIndex / 7` seconds (dayIndex 0 = Monday); multiple same-day transactions offset +0.12s each in array order.
- Pitch: `midi = 48 + 36 × ( log10(clamp(|amount|, 1, 500)) / log10(500) )`; frequency via `Tone.Frequency(midi, "midi")`. Duration 0.18s.
- Pan (per-voice `Tone.Panner`): credits −0.7 (left), debits +0.7 (right).
- Timbre by category: groceries `Synth` triangle · transport `Synth` square · bills `Synth` sawtooth · income `Synth` sine · other `Tone.PluckSynth`.
- Any `isAnomaly` note: 0.05s after it, play the C5+F#5 tritone dyad (0.12s) and trigger `haptic("alert")`.
- Call `onNote(tx.id)` at each onset so Home can flash that row (400ms amber left-border). After the sweep, aria-live: `"Played seven days. One unusual payment on Saturday."` (compose from data).

## 8. Haptic grammar — `lib/haptics.ts`

`haptic(kind: "confirm" | "alert" | "attention")`:

| kind | `navigator.vibrate` pattern | Desktop/iOS fallback (WebAudio sine blips at −18dB) |
|---|---|---|
| confirm | `[80, 60, 80]` | two 40ms blips at 1200Hz, 60ms apart |
| alert | `[40, 40, 40, 40, 40]` | three 30ms blips at 1600Hz, 40ms apart |
| attention | `[400]` | one 250ms tone at 800Hz |

If `navigator.vibrate` exists, use it AND stay silent; otherwise play the fallback blips (never both). Fallback blips also require `session.unlocked`.

## 9. Read-Back engine and Receipts

### 9.1 `ConfirmSheet.tsx`

Props: `{ readback: { id?: FixedLineId; text: string }, actionLabel: string, onConfirm(method), onCancel() }`. Bottom sheet on `--surface-raised`, focus-trapped, `role="dialog"` `aria-modal="true"`, Escape = cancel, focus returns to the invoking button on close. Contents in order: read-back text (22px) · a 120px-tall region labelled **"Double-tap to confirm"** (double-tap = two taps < 300ms apart anywhere on the sheet) · a 56px **Confirm** button · a **Cancel** text button. On open, `speak(readback)`. Confirm → `haptic("confirm")` → `onConfirm(method)` where method is `"double-tap" | "button" | "voice"`. Cancel → `speak({id:"cancel_ok"})`.

### 9.2 `state/receipts.ts` (zustand + persist, key `penny.receipts.v1`)

```ts
type Receipt = { id: string; ts: string; action: string; details: string;
  method: "double-tap" | "button" | "voice" | "auto";
  prevHash: string; hash: string };
```

`addReceipt({action, details, method})`: `ts = new Date().toISOString()`; `prevHash` = last entry's `hash` or `"0".repeat(64)`; `hash = sha256Hex(`${prevHash}|${ts}|${action}|${details}|${method}`)` using `crypto.subtle.digest("SHA-256", …)` hex-encoded (`lib/hash.ts`). `verifyChain()` recomputes every hash → `{ ok: true } | { ok: false, brokenAt: index }`.

## 11. Feature flows (exact)

### 11.1 Post Box pipeline

1. File selected → `capture.ts`: `createImageBitmap` → canvas, long edge ≤1600px → JPEG quality 0.8.
2. `ocrMask.ts` (**always before any network**): a tesseract.js `eng` worker is created when Post Box mounts (show nothing; first use may take seconds — the *masking* state covers it). `recognize(canvas)`; for every word whose text (spaces stripped) matches `/\d{4,}/` or `/^\d{2}-\d{2}-\d{2}$/`, `fillRect` a black box over its bbox padded 4px. Output `{ maskedBlob, maskedCount }`. 10s timeout → proceed with the unmasked image + the "Masking unavailable" chip.
3. Source decision: if `director.armedLetter !== "live"` → use that fixture, skip network. Else `POST /api/read-letter { imageBase64, mediaType: "image/jpeg" }` (base64 of the **masked** blob, no `data:` prefix) with an `AbortController` at **8s**.
4. Any failure (abort, non-200, invalid JSON) → play `read_fallback`, then use fixture `SCENARIOS[director.armedLetter !== "live" ? director.armedLetter : "card"]`.
5. If `letter.sensitive_content` → play `pin_privacy` first (for the pin fixture this IS the summary; do not speak a second summary).
6. Speak the summary: fixtures use their fixed audio ids; live API letters use runtime TTS. Mode switch replays: Summary → `summary_spoken`, Exact → `exact_text`, Explain → `explain_spoken` (fixtures' Exact/Explain use runtime TTS/fallback).
7. `required_action === "order_card"` → after summary, play `offer_card`; show the action button.
8. Action button → `ConfirmSheet` with `readback = {id:"readback_card", text:"Ordering a replacement debit card to your home address at 42 Lavender Grove. It will arrive in five working days. Double-tap to confirm."}`. On confirm: `addReceipt({ action: "Replacement card ordered", details: "Arriving in 5 working days to home address", method })` → `speak({id:"done_receipt"})`.
9. `required_action === "scam_alert"` → §11.4. `"none"` → summary only.

### 11.2 Tap & Tell (director-triggered)

Director push → `haptic("attention")` → `TapTellSheet` (same dialog rules as ConfirmSheet): merchant 28px · amount 40px · "Double-tap to approve" region · Cancel. Not quiet: play `tap_coffee` / `tap_unknown`. Quiet: no speech; the sheet is the text card, plus caption row "Quiet Mode". ## 13. Serverless functions (Vercel, Node runtime, plain fetch, keys never reach the client)

### 13.1 `api/read-letter.ts`

`export const config = { api: { bodyParser: { sizeLimit: "6mb" } } };` Default-export `(req, res)`. Accept POST `{ imageBase64: string, mediaType: "image/jpeg" }`. Call the Google Gemini API (reference: https://ai.google.dev/gemini-api/docs):

```
POST https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:generateContent
headers: {
  "x-goog-api-key": process.env.GEMINI_API_KEY,
  "content-type": "application/json"
}
body: {
  "systemInstruction": { "parts": [{ "text": SYSTEM_PROMPT }] },
  "contents": [{ "role": "user", "parts": [
    { "inline_data": { "mime_type": "image/jpeg", "data": imageBase64 } },
    { "text": "Read this letter." }
  ]}],
  "generationConfig": {
    "temperature": 0,
    "maxOutputTokens": 4096,
    "responseMimeType": "application/json"
  }
}
```

**Vendor note.** This section originally specified the Claude API (`claude-sonnet-4-6`, `max_tokens` 1024). Changed to Gemini because the project has no Anthropic credit; a §13.1 that cannot be called is worse than one naming a different vendor. Everything §13.1 actually constrains is unchanged — the same `SYSTEM_PROMPT` verbatim, the same masked JPEG, temperature 0, the same seven-key contract and five `required_action` values, and the same "any failure → 502" so §11.1 step 4's fixture fallback still carries the demo. `maxOutputTokens` is 4096 rather than 1024 because Gemini draws reasoning tokens from the same budget as the reply, and `exact_text` is the whole letter verbatim.

**Model choice is a latency decision.** §11.1 step 3 aborts the call at 8s, and that budget also covers a phone uploading a ~1600px JPEG over mobile data, so the model is pinned by measurement against this project's key, not by reputation. On the three §5.3 prop letters at temperature 0, `gemini-3.1-flash-lite` returned the right verdict on all three (`order_card`, `scam_alert`, and `none` + `sensitive_content: true` with the PIN masked to `[hidden]`) in 1.4–1.8s, repeatably. `gemini-3.5-flash` agreed but took 5.7–6.3s — inside the abort by under two seconds before the upload is counted — and returned 403 on one of the three. The 2.5 family is retired for new keys and `gemini-3.6-flash` is not permitted for this key. Re-measure before changing the pin.

`SYSTEM_PROMPT` — copy verbatim:

> You are Penny, a bank's accessibility assistant for blind customers. Look at this photographed letter and return ONLY a JSON object, no markdown fences, no prose, with exactly these keys: {"sender": string, "letter_type": string, "summary_spoken": string (max 40 words, warm, plain English, no jargon, written to be read aloud), "explain_spoken": string (max 80 words, plain-English explanation of what this letter means for the customer), "required_action": one of "none" | "order_card" | "confirm_address" | "form_fill" | "scam_alert", "sensitive_content": boolean (true if a PIN, password, or full card number is visible), "exact_text": string (the letter verbatim)}. If any card number or PIN is visible, replace it with [hidden] everywhere, including exact_text.

Response handling: `data.candidates[0].content.parts[0].text` → strip any ```json fences → `JSON.parse` → validate all seven keys exist and `required_action` is one of the five values (map `confirm_address`/`form_fill` to `none` client-side; only `order_card` and `scam_alert` have UI) → `res.json({ ok: true, letter })`. Any failure → `res.status(502).json({ ok: false })` (the client's fixture fallback handles it). Missing `GEMINI_API_KEY` → immediate 502.

### 13.2 `api/tts.ts`

POST `{ text: string }` (reject > 600 chars). Resolve the voice once per cold start: `GET https://api.elevenlabs.io/v1/voices` with header `{ "xi-api-key": process.env.ELEVENLABS_API_KEY }` → pick the voice named `"Alice"`; if absent, the first voice whose labels/description contain "British"; else the first voice. Then:

```
POST https://api.elevenlabs.io/v1/text-to-speech/{voiceId}?output_format=mp3_44100_128
headers: { "xi-api-key": KEY, "content-type": "application/json" }
body: { "text", "model_id": "eleven_multilingual_v2",
        "voice_settings": { "stability": 0.5, "similarity_boost": 0.75 } }
```

Stream the response back with `content-type: audio/mpeg`. Missing key or upstream error → 502 (client falls back to `speechSynthesis`).

## 15. Accessibility requirements (non-negotiable) + TalkBack checklist

- One `LiveRegion.tsx` singleton: `<div aria-live="polite" role="status" class="sr-only">`; every spoken string is mirrored here (§6.3 step 1).
- The live region is a **serial queue, not a slot**. `announce()` appends; messages render **one at a time** with a **minimum 900ms gap** between them, and a message is **never overwritten** by the next. A burst — §11.5's read-aloud, or §6.1's `greet` followed by §7.1's Glance completion line — drains in order and is heard in full.
- While draining, the region carries `data-live-busy="true"`; it reads `"false"` only once every queued message has rendered *and* its gap has elapsed *and* no audio is still in flight (§6.3 step 6's activity refcount). Audio in flight counts because §7.1/§7.2 post their completion lines at the *end* of an earcon, so a queue that is momentarily empty does not mean nothing more is coming.
- The live region is the **sole announcement channel**. `TextCard.tsx` carries **no** `role="status"` — this supersedes the attribute named in §11.3. The card is a visual surface only; the same string reaching a screen reader from both the card and the live region would announce it twice, which is the failure the TalkBack pass item 5 below exists to catch.
- Every interactive element has an accessible name; inputs are labelled; the photo input uses a real `<label>`.
- Landmarks: `header`, `main`, `nav`. Heading structure: exactly one `h1` per screen (the Header title).
- Focus: visible ring everywhere (§4); sheets trap focus and restore it on close; Escape closes sheets.
- DOM order = §10 canonical order = visual order. No `tabindex` > 0 anywhere. The director trigger is `aria-hidden` and unfocusable.
- `prefers-reduced-motion` disables the sound-dot pulse, row flashes, and sheet transitions.
- Contrast: body text ≥ 7:1; amber is used for large text/UI components only; text on amber buttons is `#101418`.

TalkBack pass (run before filming; all must hold): 1) swipe order on each screen matches §10; 2) the balance reads label → amount → health → bills as one coherent sequence; 3) mode switch announces the selected mode; 4) ConfirmSheet announces the read-back on open and confirms are reachable by double-tap gesture AND the Confirm button; 5) TextCards are announced once, not repeatedly; 6) anomaly rows announce "unusual payment"; 7) the Journey slider announces years via `aria-valuetext`; 8) no unlabelled buttons anywhere (axe run in §16 must agree); 9) receipts read as full sentences; 10) mic button announces listening state.

## 16. Layout Lock CI gate — `ci/layout-lock/check.mjs`

Algorithm:

1. Run `vite build` (inheriting `VITE_BREAK_LAYOUT` if set), then spawn `vite preview --port 4173 --strictPort`; wait for the port.
2. Launch Playwright Chromium, viewport 390×844. For each route in `["/", "/postbox", "/receipts", "/settings", "/journey"]`: navigate, click `body` once (dismisses Splash), wait for `networkidle`, **then wait for the live region to report `data-live-busy="false"` (§15) — never a fixed sleep** — then `const snap = await page.locator("body").ariaSnapshot()` (Playwright ≥ 1.49). Normalise: trim trailing whitespace per line.
   The extra wait is not optional: the splash tap starts `greet` and then `glance()`, and §7.1 posts the Glance's completion line into the live region on a timer *after* the earcon (measured at 1043ms after the tap). `networkidle` alone therefore captures the region mid-flight — sometimes empty, sometimes not — and the snapshot is a race rather than a baseline. All five routes must reuse **one browser tab**: `session.unlocked` lives in `sessionStorage`, so a fresh tab per route re-arms the Splash and §6.1's navigate-to-Home turns four of the five baselines into copies of Home.
3. Also run `new AxeBuilder({ page }).analyze()` per route; collect violations with impact `serious` or `critical`.
4. `--baseline` mode: **refuse unless `process.env.LOCK_MIGRATION === "1"`**, printing exactly: `Refusing to move the baseline without LOCK_MIGRATION=1 — Layout Lock exists so this is deliberate.` With the flag, write each snapshot to `ci/layout-lock/baseline/{route-name}.snap.yml` (route name: `home`, `postbox`, `receipts`, `settings`, `journey`) and exit 0.
5. Check mode: diff each snapshot against its baseline. On mismatch print a unified diff (first 40 lines) and the line: `BUILD FAILED — accessibility regression on {route}: structure changed without a migration flag` · on axe violations print each as `BUILD FAILED — {impact} accessibility violation on {route}: {id} ({help})`. Exit 1 on any failure; exit 0 with `Layout Lock ✓ {n} routes verified, 0 violations` otherwise.

`lock:demo-break` builds with `VITE_BREAK_LAYOUT=1` (Home swaps its two buttons, §10) and must fail with the "regression on /" message — this is demonstrated live in Q&A, so the output wording matters.
